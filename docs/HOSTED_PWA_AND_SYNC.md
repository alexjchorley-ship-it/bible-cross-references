# Hosted Bible Study — deployment and cross-device sync

## Current deployment

The Pages workflow in `.github/workflows/pages.yml` builds the app at:

https://alexjchorley-ship-it.github.io/bible-cross-references/

It uses the existing Vite subpath, static HTML per language, PWA manifest and service worker. The Bible is public; there is no private data in static build artifacts.

**Owner action required once:** GitHub repository → **Settings → Pages** → **Build and deployment → Source: GitHub Actions**. After merging the Pages workflow to `main`, open **Actions → Publish Bible Study PWA**, verify success, then visit the URL on the phone and laptop. Install using the browser's *Install app* or *Add to Home screen* action.

## Important: device data is not synced by Pages

The current reader stores its notes and highlights in IndexedDB, **per browser and per origin**. Local Windows `127.0.0.1:4173` data does not appear at GitHub Pages automatically. Before switching origins, **export the JSON backup** from My Notebook, then **import it** into the hosted application. Do not discard the local backup. Another phone/browser also needs the manual import until cloud synchronisation is implemented.

## Cloud synchronisation dependency

Supabase credentials and project ownership **cannot be generated by GitHub Pages**. Never put a Supabase `service_role` key or database password into the frontend, repository, or Actions.

For automatic sync, the owner needs to create a free Supabase project at https://supabase.com/dashboard, then provide the **project URL and publishable/anon key only** (both designed to be used by a browser). The application needs Supabase authentication, Row Level Security (RLS) for every row, an initial upload/merge that preserves existing IndexedDB notes, durable deletion tombstones, offline retries, and conflict testing before cloud sync is enabled. There is **no automatic cloud sync in the present Pages workflow**.

Do not expose personal notes in public GitHub commits or CI logs, even if they are not considered confidential. A publicly readable database should never be necessary merely because the source repository is public.

## Device acceptance checklist

1. The hosted URL loads in Android Chrome and Windows Chrome/Edge.
2. Book → chapter navigation works and opens Threads.
3. The PWA installs alongside the original upstream app, as a separate origin.
4. Both annotation actions work; notes survive a reload.
5. Browser DevTools/airplane mode verify offline functionality after caching.
6. JSON export and import transfer existing notes to the hosted origin.
7. **After** the database-backed sync feature is built and connected, verify online and offline edits made on both devices converge without data loss.
